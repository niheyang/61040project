# P3 narrated recording plan

Target length: 1 minute 45 seconds to 2 minutes. This is a script, not a completed recording. Record the actual beta and upload the video separately; keep the video file out of Git.

| Time | Show | Suggested narration |
| --- | --- | --- |
| 0:00–0:15 | Alice's conversation with Bob; Bob's view beside it | “Sometimes I want to share something with a friend while they're busy. If I wait, I might forget. Catchup explores letting me share now while my friend chooses when new messages become available.” |
| 0:15–0:35 | Bob's closed window. Alice sends one short share. | “Alice sends a link to Bob. Her message says Waiting for catch-up. Catchup has stored it, but Bob sees no pending message, preview, or waiting count. He can still browse previous conversations.” |
| 0:35–0:55 | Bob selects Catch up now and opens Alice's conversation. | “Bob chooses to catch up. This opens a 15-minute receiving window across his chats. Alice's share appears with its original creation time. Available tells Alice the message can be accessed; it isn't a read receipt.” |
| 0:55–1:15 | Alice sends again while Bob's window is open; Bob replies. | “Further shares arriving during this window also appear. Bob can reply in the same friend conversation. His reply follows Alice's own receiving window.” |
| 1:15–1:30 | Bob saves one incoming message, filters Saved only, then returns. | “Bob can privately save a share he wants to return to. Saved is a bookmark, independent of whether a message is waiting or available.” |
| 1:30–1:50 | Bob ends catch-up; Alice sends another share; Bob browses released history. | “Ending catch-up stops new incoming shares from appearing. Earlier conversations remain available. The next share waits for Bob's next window.” |
| 1:50–2:00 | End on the conversation. | “The question for testing is whether this deliberate receiving moment helps friends return to exchanges they value, compared with their existing muted chats.” |

Before recording, create the two demonstration accounts through the interface and have their usernames ready. Keep messages short enough to read on screen. Record one ordinary journey with your own narration; the detailed error and access checks belong in the test output and notebook.

After uploading, add a working YouTube link to the project README. Verify that classmates and staff can open it.
